# 01 · 后端与数据库（ASP.NET Core + MySQL）

> 本模块在 **Unity 工程之外**新建一个 ASP.NET Core Web API 项目，负责账号、云存档、排行榜。Unity 通过 HTTP 访问它。建议后端项目放在 `f:\UnityProgram\毕设v.0.1\Backend\` 同级目录（不要放进 Assets，避免 Unity 误导入）。

---

## 提示词 1-A — 数据库表结构设计

【目标工具】Codely
【使用时机】后端开工第一步
【提示词正文】

```
请为我的 HD2D 双人合作解密游戏设计 MySQL 数据库表结构，只输出 SQL 建表语句（DDL）与字段说明，不要写后端代码。要求：

1. 表 users（账号）
   - id（自增主键）、username（唯一）、password_hash（密码哈希，用 BCrypt，不存明文）、created_at、updated_at
2. 表 saves（云存档 / 关卡进度）
   - id、user_id（外键）、level_id、is_cleared（是否通关）、best_time_seconds（最快通关秒数）、collected（拾取物/收集情况，JSON 文本）、updated_at
   - 建议 (user_id, level_id) 建唯一索引，实现「每个玩家每关一条记录」的 upsert
3. 表 leaderboard（排行榜）
   - id、user_id（外键）、total_cleared（通关关卡数）、total_time_seconds（总用时）、score（可选，综合得分）、updated_at
   - 说明如何用一条 SQL 查询「按 total_cleared 降序、total_time_seconds 升序」取前 50 名的排行榜，并关联 username

约束：
- 表名、字段名用小写 snake_case
- 字符集 utf8mb4
- 外键 ON DELETE CASCADE（删除用户时级联删除其存档与榜单位）
- 给我完整的 CREATE TABLE 语句和索引定义

请先给出表结构设计说明，再给出可直接在 MySQL 执行的 SQL。
```

【预期产出】三张表的完整 DDL + 排行榜 Top50 查询 SQL + 唯一索引 upsert 说明。在 MySQL 客户端（或 Navicat/phpMyAdmin）执行确认无报错。

【目标工具】Codely
【使用时机】表建好后
【提示词正文】

```
请帮我搭建一个 ASP.NET Core Web API 项目骨架，用于给 Unity 客户端提供账号、云存档、排行榜服务。要求：

1. 项目类型：ASP.NET Core Web API，.NET 8（若环境是 .NET 6 也请说明差异），C#。

5. 全局异常处理中间件，返回统一的 JSON 错误格式 { "code": 错误码, "message": "错误信息" }。
6. 先只搭骨架（空 Controller 返回 OK），能 `dotnet run` 启动、Swagger 能打开即可，暂不实现具体业务。

请给出关键文件（.csproj、Program.cs、AppDbContext.cs、一个示例 Controller）的完整代码，并说明创建步骤与依赖安装命令。
```

【预期产出】可 `dotnet run` 启动的 API 骨架，Swagger 页面可见。记录好 MySQL 连接字符串。

## 提示词 1-C — 登录注册接口（含鉴权）

【目标工具】Codely
【使用时机】骨架跑通后
【提示词正文】

```
在上面的 ASP.NET Core 项目里实现账号登录注册接口。要求：

1. POST /api/auth/register —— 入参 username、password；校验用户名唯一、密码长度≥6；BCrypt 哈希后入库；返回 user_id 与 token。
2. POST /api/auth/login —— 校验密码，成功返回 user_id、token。
3. 鉴权方案：用简单的 JWT（System.IdentityModel.Tokens.Jwt）签发 token，有效期 7 天；受保护的接口（存档、排行榜提交）需带 Authorization: Bearer <token>。
4. 统一返回格式：成功 { "code": 0, "data": {...} }；失败 { "code": 非0, "message": "..." }。
5. 给出 JWT 中间件配置、[Authorize] 的使用方式、如何从 token 中解析 user_id（ClaimsPrincipal）。

请给出 AuthController.cs、AuthService.cs、JwtHelper、Program.cs 中鉴权配置的完整代码。
```

【预期产出】注册/登录接口可用，能拿到 token；无 token 访问受保护接口返回 401。

## 提示词 1-D — 云存档与排行榜接口

【目标工具】Codely
【使用时机】鉴权跑通后
【提示词正文】

```
继续实现云存档与排行榜接口（均需登录态）。要求：

1. POST /api/save —— 入参 level_id、is_cleared、best_time_seconds、collected(JSON)；实现 upsert（存在则更新，不存在则插入），依赖 (user_id, level_id) 唯一索引。
2. GET /api/save?level_id=xxx —— 返回当前用户该关卡的存档；不带 level_id 则返回全部关卡存档列表。
3. POST /api/leaderboard/submit —— 通关后上报，更新当前用户在 leaderboard 表的 total_cleared、total_time_seconds（累加/取最优，逻辑要说明清楚）。
4. GET /api/leaderboard/top?limit=50 —— 返回排行榜前 50，关联 username，按 total_cleared 降序、total_time_seconds 升序。
5. 所有接口入参用 DTO 校验（必填、范围），错误返回统一格式。

请给出 SaveController.cs、LeaderboardController.cs、SaveService.cs、LeaderboardService.cs 及对应 DTO 的完整代码。
```

【预期产出】存档可读写、排行榜可提交与查询，用 Postman 或 curl 验证通过。

## 提示词 1-E — Unity 侧 HTTP 客户端封装

【目标工具】Codely
【使用时机】后端接口全部跑通后，回到 Unity 工程
【提示词正文】

```
现在回到 Unity 工程（团结引擎 2022.3，URP，Netcode 1.12.2）。请帮我封装一个 HTTP 客户端，用于访问已建好的 ASP.NET Core 后端（登录/存档/排行榜）。

要求：
1. 新建 Assets/Scripts/Net/ApiClient.cs，用 UnityWebRequest 封装 GET/POST JSON 请求，支持携带 Bearer token，支持协程/async 两种调用方式（以协程为主，说明 async 用 UnityEngine.Networking 需注意的线程问题）。
2. 通用响应解析：后端返回 { "code": int, "data": ..., "message": string }，封装成一个泛型 ApiResult<T> 结构体，用 JsonUtility 或 Newtonsoft.Json（说明选择）。
3. 提供具体方法：Register、Login、SaveProgress、GetSave、SubmitLeaderboard、GetLeaderboardTop。
4. 新建 Assets/Scripts/Net/UserSession.cs 单例，保存登录后的 user_id 与 token，供全工程访问。
5. 后端地址做成可配置：一个静态字符串 BaseUrl，先用 http://localhost:5000，并注释说明局域网/云部署时如何改。
6. 注意：不要用 linearVelocity、NetworkTickRate 等 Unity 6 API（本项目是 2022.3）。

请给出 ApiClient.cs 与 UserSession.cs 的完整代码，以及一个简单的调用示例（登录成功后打印 user_id）。
```

【预期产出】Unity 内能通过 `ApiClient.Instance.Login(...)` 成功登录本地后端并打印结果；无编译错误。
