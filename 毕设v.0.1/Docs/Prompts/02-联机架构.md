# 02 · 联机架构（Netcode + Unity Relay）

> 本模块实现互联网联机：主机通过 Unity Relay 分配 join code，客机凭 code 加入。所有实时状态走 Netcode，不写数据库。请按顺序贴给 Codely，每段生成后先在 Unity 编译通过再继续。

---

## 提示词 2-A — Unity Relay + Unity Transport 接入

【目标工具】Codely
【使用时机】联机第一步
【提示词正文】

```
我要给 Unity 工程（团结引擎 2022.3，Netcode for GameObjects 1.12.2）接入 Unity Relay 与 Unity Transport，实现互联网联机。请先帮我梳理接入步骤与配置，再给出核心代码。

要求：
1. 需要安装哪些包（com.unity.services.relay、com.unity.transport.utp 等），并在 Unity Services 里开启 Relay 服务的说明。
2. 新建 Assets/Scripts/Net/NetworkManagerUI.cs 或扩展 GameManager，负责：
   - 创建房间：调用 Relay 分配 allocation 与 join code，主机以 UnityTransport + Relay 作为连接数据启动 Host。
   - 加入房间：客机输入 join code，调用 Relay join，得到连接数据后启动 Client。
3. 用 NetworkManager 的 NetworkConfig 配置 UnityTransport（协议、最大连接数 2），把 Relay 的 server data 填给 UnityTransport 的 SetRelayServerData。
4. 断线回调：OnClientDisconnectCallback，弹出「连接中断」提示并回主菜单。
5. 重要兼容点：团结引擎 2022.3 的 NetworkConfig 没有 NetworkTickRate 字段，不要设置它；不要用 Unity 6 的 linearVelocity 等 API。

请给出依赖包清单、Relay 服务的开启步骤、以及 NetworkManagerUI.cs / RelayUtils.cs（分配与加入的封装）的完整代码。若需 async/await，说明 Unity 协程与 async 的搭配。
```

【预期产出】两台设备（或双开）能通过 join code 完成 Host/Client 连接，控制台打印连接成功。若 Relay 需联网，先在 Unity Dashboard 创建项目并开启 Relay。

## 提示词 2-B — 大厅/房间管理与 join code 流程

【目标工具】Codely
【使用时机】Relay 连通后
【提示词正文】

```
请基于上面的 Relay 接入，完善大厅/房间管理流程，并把它接到现有 UIManager/GameManager。要求：

1. 主菜单两个按钮：「创建房间」「加入房间」。
2. 创建房间：主机登录态有效的前提下（UserSession 有 token）创建 Relay 房间，界面显示 join code（6 位），供队友输入。
3. 加入房间：输入 join code，连上后进入同一场景。
4. 场景加载：用 NetworkManager.SceneManager 加载游戏场景（Assets/Scenes/SampleScene.unity），保证主机与客机同步进场景；说明 NetworkObject 与场景加载的时序。
5. 角色生成：两台玩家进入场景后各自生成自己的玩家角色（区分 Player 1 / Player 2），用 NetworkManager 的 PlayerPrefab 或手动 Spawn。
6. 处理重复加入/满员/无效 code 的错误提示。

请给出 RoomUIManager.cs（或改造 GameManager）与相关流程代码，说明 NetworkSceneManager 的正确用法。
```

【预期产出】主机建房看到 code，客机输 code 加入，双方进入同一场景并各生成角色。

## 提示词 2-C — 玩家同步（NetworkTransform + NetworkAnimator）

【目标工具】Codely
【使用时机】双角色生成后
【提示词正文】

```
请把现有 PlayerMove.cs 改造成联机同步，让两名玩家的位置与动画互相同步。要求：

1. 玩家预制体（Assets/Prefabs/player.prefab、Player 1.prefab）挂 NetworkObject、NetworkTransform、NetworkAnimator。
2. 角色移动输入只在本机生效，位置通过 NetworkTransform 同步；说明 owner 权限：只有拥有者能写，其他客户端读。
3. 动画：用 NetworkAnimator 同步 Animator 参数（现有 idle/run 等序列帧动画在 Assets/素材 下）。
4. 双角色区分：主机生成 Player 1，客机生成 Player 2，颜色或名字区分，避免混淆。
5. 相机：本地玩家用自己的跟随相机；远程玩家不加相机。说明如何判断 IsOwner / IsLocalPlayer。
6. 兼容点：刚体速度用 Rigidbody.velocity（不是 linearVelocity）。

请给出改造后的 PlayerMove.cs（或新增 NetworkPlayer.cs）完整代码，并说明预制体需要挂哪些组件及参数设置。
```

【预期产出】两名玩家移动与动画实时互相同步，各自视角正确。

## 提示词 2-D — 谜题状态同步（NetworkVariable + RPC）

【目标工具】Codely
【使用时机】玩家同步稳定后
【提示词正文】

```
请把现有谜题系统（Assets/Scripts/Puzzle/ 下）改造成网络同步，保证两名玩家看到的机关状态一致。要求：

1. 通用模式：每个可交互机关（PressurePlate、PuzzleDoor、LaserReceiver、ExitZone 等）挂 NetworkObject，用 NetworkVariable<bool> 保存状态（如门是否开启、压力板是否被压）。
2. 服务器权威：状态变更由拥有该 NetworkObject 的服务器端负责；客户端通过 ServerRpc 发送「交互/触发」请求，服务器改 NetworkVariable，再自动同步到所有客户端。
3. 事件联动：门打开/关闭、激光通断等状态变化时，所有客户端都能收到通知（NetworkVariable 的 OnValueChanged 回调）并播放对应表现（音效、动画）。
4. 给出一个完整示例：把一个 PressurePlate + PuzzleDoor 改成「两人同时踩两个压力板才开门」的网络版（若尚未有双压力板逻辑，可先做单个压力板开门的网络同步）。
5. 注意：现有 PuzzleManager.cs 若承担了单机逻辑，请说明如何与网络同步并存，避免单机/联机状态冲突。

请给出改造后的 PressurePlate.cs、PuzzleDoor.cs（网络版）完整代码，以及 NetworkVariable/RPC 的使用示例。
```

【预期产出】双方看到的门/压力板状态一致，任一方触发都能正确同步到另一方。
