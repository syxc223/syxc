# 06 · 关卡与地图（关卡设计 + Tilemap 搭建）

> 本模块用 Codely 产出「关卡设计文档」，再用 Tilemap 把 04 号文件生成的地面/墙面 tile 铺成场景。建议先设计 1 个完整演示关卡，再扩充。

---

## 提示词 6-A — 关卡整体设计（先出关卡文档）

【目标工具】Codely
【使用时机】谜题机制（03）与素材（04）就绪后
【提示词正文】

```
请为我的 HD2D 双人合作解谜游戏设计关卡。先输出「关卡设计文档」，不要写代码/建场景。要求：

1. 定位：这是毕设演示，需要 1 个主演示关卡 + 2 个教学/进阶关，共 3 关，难度递增。
2. 每关输出：
   - 关卡主题与视觉氛围（对应 04 号文件的 tile 风格）
   - 谜题清单与顺序（用已有机制：双压力板门、传送门配合、激光折射、拾取方块）
   - 每个谜题的「双人协作点」明确写清楚：为什么一个人过不去
   - 出口/通关条件
3. 难度曲线：第 1 关教学（一个双压力板门 + 一个传送门），第 2 关进阶（传送门 + 激光接力），第 3 关综合（多机制组合 + 限时/会合）。
4. 每关给一张「俯视布局示意图」（用 ASCII 字符画即可，标注：出生点 P1/P2、压力板 A/B、门 D、传送门 O/B、激光 L、出口 E）。
5. 说明每关预期通关时长（3–5 分钟为宜）。

请先给出 3 关的完整设计文档。
```

【预期产出】3 关的设计文档 + ASCII 布局图，协作点清晰。据此可开始搭场景。

---

## 提示词 6-B — Tilemap 搭建场景

【目标工具】Codely
【使用时机】关卡设计确定后
【提示词正文】

```
请指导我（或给出步骤）用 Unity Tilemap 搭建第 1 关场景。要求：

1. 使用 04 号文件生成的 tile 素材（地面、墙壁）切好 tile 后，在 SampleScene 里建 Grid + Tilemap（Ground 层、Wall 层）。
2. 地面层：铺可通行的地面；墙壁层：铺带碰撞的墙（用 TilemapCollider2D 或 3D 碰撞，取决于你的游戏是 2D 还是 2.5D，请先确认项目实际用 2D 还是 3D 物理）。
3. 说明 Grid 的 Cell Size、Tile 的 Pixels Per Unit 设置，保证像素不糊、对齐正确。
4. 按 6-A 的布局图摆放：出生点 P1/P2、压力板、门、传送门、激光、出口等机关预制体（机关脚本已在 Puzzle/Portal 下）。
5. 光影：HD2D 需要 3D 光照打在 2D 精灵上，说明如何给场景加灯光/体积光/阴影（URP 14），让像素角色有立体感。
6. 兼容点：Unity 2022.3，别用 Unity 6 API（如 Rigidbody.velocity 而非 linearVelocity）。

请先确认项目物理是 2D 还是 3D，再给出 Tilemap 搭建步骤与必要设置。
```

【预期产出】第 1 关场景搭好，机关摆放正确，光影有 HD2D 立体感。

## 提示词 6-C — 关卡配置驱动（进阶，可扩展性）

【目标工具】Codely
【使用时机】想要用配置而非硬编码管关卡时
【提示词正文】

```
为了后续方便扩充关卡，请帮我设计一个「关卡配置」方案。要求：

1. 用 ScriptableObject（如 LevelConfig）存储每关的：关卡 id、名称、tile 主题、机关列表（类型 + 位置 + 参数）、出生点、出口、通关条件。
2. 关卡在运行时根据 LevelConfig 自动摆放机关（而不是每个机关都手动拖进场景），说明如何实例化机关预制体并挂到 NetworkObject（联机时需统一 Spawn）。
3. 给出 LevelConfig.cs 与一个 LevelLoader.cs 的代码，以及一个示例 LevelConfig 资产如何填。
4. 说明如何与 01 号文件的存档（level_id）与排行榜打通。
5. 兼容点：Unity 2022.3 API。

请给出 LevelConfig.cs、LevelLoader.cs 完整代码与示例配置说明。
```

【预期产出】新增关卡只需新建一个 LevelConfig 资产，无需重搭场景逻辑。
