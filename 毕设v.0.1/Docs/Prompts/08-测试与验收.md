# 08 · 测试与验收（联机测试 + 打包发布）

> 本模块给出联机测试清单与打包发布步骤，是毕设答辩前的收尾。测试重点在「双人联机一致性」与「跨网络可达性」。

---

## 提示词 8-A — 联机测试清单

【目标工具】Codely
【使用时机】全功能完成后，打包前
【提示词正文】

```
请为我的 HD2D 双人合作解密游戏生成一份「联机测试清单」。要求覆盖：

1. 连接层（Relay）：
   - 创建房间 → 显示 join code
   - 加入房间 → 输入错误 code 的处理
   - 满员（第 3 人加入）拒绝
   - 断线（拔网/杀进程）双方的表现与重连提示
2. 玩家同步：
   - 双方位置/动画实时一致
   - 各自的相机与输入不串（A 的操作不影响 B）
3. 谜题同步：
   - 双压力板门：两人同时踩开、任一人离开关，双方一致
   - 传送门：A 开的门 B 能看到并穿过，传送无抖动
   - 激光/方块/门：状态双方一致
4. 数据层（后端 MySQL）：
   - 登录/注册成功与失败（重复用户名、错误密码）
   - 云存档读写、排行榜提交与 Top50 查询
   - 只有主机上报、不重复计分的验证
5. 异常与性能：
   - 高延迟/弱网下的表现（卡顿、位置回弹）
   - 长时间游玩的稳定性（是否内存泄漏/掉线）

请把每项做成「测试步骤 + 预期结果 + 实际结果」的表格，我逐项打勾。
```

【预期产出】一份可勾选的测试清单表格，覆盖联机、谜题、数据、异常四类。

## 提示词 8-B — 弱网与断线处理完善

【目标工具】Codely
【使用时机】测试发现断线/同步问题时
【提示词正文】

```
测试发现联机在断线/弱网时体验不佳，请帮我完善健壮性。要求：

1. 断线检测与提示：主机断开时，客机 OnClientDisconnectCallback 弹「主机已断开」，并回主菜单；客机断开时主机弹「队友已断开」。
2. 状态回退：弱网导致位置跳变时，说明 Netcode 的插值/外推配置（NetworkTransform 的 interpolation 参数）如何调。
3. 重连策略：说明是否支持断线重连；若当前架构不支持，明确说明原因（host-client 模型限制），并给出「重开房间」的兜底流程。
4. 后端超时：HTTP 请求超时/失败时，Unity 侧重试与提示（ApiClient 加超时与重试）。
5. 兼容点：Netcode 1.12.2 的 NetworkTransform 参数名，别用 Unity 6 语法。

请给出断线处理与 HTTP 重试的代码改造，并说明 NetworkTransform 同步参数建议。
```

【预期产出】断线有明确提示，HTTP 请求有超时重试，弱网表现改善。

## 提示词 8-C — 打包发布（Build Settings）

【目标工具】Codely
【使用时机】测试通过后
【提示词正文】

```
请指导我打包发布这款游戏。要求：

1. 平台：Windows（PC 双开联机测试）+ 可选 Android（毕设演示用 PC 为主）。
2. Build Settings：场景列表（SampleScene 等）、压缩方式、IL2CPP vs Mono 的选择与理由。
3. Relay 上线配置：说明从开发用（本地测试）切换到正式 Relay 环境需要改什么（Project ID、环境变量），UnityTransport 如何配置。
4. 后端部署：ASP.NET Core 后端如何发布（dotnet publish）并部署到云服务器（或局域网），MySQL 连接字符串如何切换，Unity 端 BaseUrl 如何改成公网地址。
5. 常见坑：防火墙/端口、HTTPS 要求、Relay 区域（region）选择、内网穿透方案（若只在局域网答辩可说明本地部署）。
6. 给出一份「答辩演示 checklist」：如何准备两台设备 + 一个后端，保证现场演示顺利。

请给出打包步骤、后端部署步骤与答辩演示清单。
```

【预期产出】可打包出 Windows 版，后端可部署，有答辩演示预案。

4. 备用方案：如果现场网络不稳，如何快速切到局域网演示。

请给出结构化演示脚本与常见问答。
