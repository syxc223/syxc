# 第三关《双生仓库》关卡设计与实现说明

> 实现日期：2026-10-06 ｜ 场景：`Assets/Scenes/Level3.unity` ｜ 目标：把「双人协作」做成必须，而不是可选
>
> 备份：改动前的空场景已备份到 `Backups/Level3_pre_coop.unity`。

---

## 1. 设计定位

两条**一模一样**的仓库长廊（右厅是左厅整体 +10.7 沿 X 平移复制），被中隔墙完全隔开。
P1 在左厅、P2 在右厅，**互相看不见**，只能靠游戏内聊天（T）沟通。

三条核心协作点（与用户确认）：

| 协作点 | 在本关的实现 |
|---|---|
| **同时操作** | 出口闸门需要两块压力板**同时**被压住（`_requireAllPlates = true`） |
| **看门人** | 第 1 段：一人踩住本厅的板，才能打开**对面**走廊的闸门让同伴通过 |
| **传递搬运** | 第 2 段：唯一的箱子在右厅，必须经中隔墙上的**传递窗**交给左厅的人 |

设计原则：**每一道闸门都由「对面走廊」或「两厅共同」的机关控制** —— 一个人无法单独推进。

- 每道横向隔墙由两段 `SM_Wall01` 组成，中间留 **2.4 宽 × 3.1 高** 的门洞；门洞上方补门楣，门体关闭时完全封死。
- 门体 2.5×3.1×0.5（`DoorMat`），打开时垂直下沉 3.2（`_openOffset = (0,-3.2,0)`）。
- 传递窗：中隔墙 z∈[11.9, 14.3] 处被切开，横梁占 y≥1.2，下方 1.2 高的开口只放行箱子。

## 3. 通关流程（预期解法）

1. **教学死锁**：两人各自踩住自己厅的板 → 两扇门都开着，但谁都不能松脚离开（一眼看懂"必须轮流"）。
2. **看门人**：P1 踩 压力板_L1 → 闸门_R1 开 → P2 进右厅 bay2；P2 踩 压力板_R2 → 闸门_L1 开 → P1 进左厅 bay2。
3. **传递搬运**：P2 把 可搬运箱_R 推到中隔墙的传递窗（z≈13.1）推过去 → P1 在左厅接到箱子 → 放到 压力板_L2b 上。
   → 闸门_L2 / 闸门_R2 同时常开 → 两人各自进入 bay3。
4. **同时操作收尾**：P1 把 可搬运箱_L 放到 压力板_L3b（闸门_R3 常开）；P2 站上 压力板_R3b
   → 闸门_L3 满足 AND → P1 走向 Exit_P1；P2 离开板后 闸门_L3 关闭但 P1 已在出口内 → P2 走向 Exit_P2。
5. 两人都在出口 → `LevelManager` 判定通关 → 5 秒后回大厅。

## 4. 实现要点

### 场景骨架（从 Level1 克隆复用的对象）
`LevelManager`（关卡名"第三关：双生仓库"、出生点、HUD 引用）、`LevelCanvas`（StatusText / CompletePanel / CompleteText）、
`ChatNetwork`（**本关必须要有，否则联机聊天发不出去**）、`CameraBounds`（z 夹取 -11~48）、`EventSystem`。

### 脚本改动
| 脚本 | 改动 |
|---|---|
| `Scripts/Gameplay/PressurePlate.cs` | 占位者改为**服务器重叠查询**（每 0.2s `OverlapBoxNonAlloc`）识别 `PlayerMove` / `PickupCube`，避免瞬移/静止的角色控制器不触发 Trigger；离开或被销毁（掉线）自动释放，修复计数卡死。开合播 `PlatePress`/`PlateRelease`。 |
| `Scripts/Gameplay/LockedDoor.cs` | 新增 `_requireAllPlates`（AND 模式）、`_displayName`、`_announceState`（状态变化 HUD 提示，让玩家知道"对面走廊的门开了"）。保留原 OR 行为与垂直滑动。 |
| `Scripts/PlayerMove.cs` | 新增 `OnControllerColliderHit` 推箱（仅对 `PickupCube` 生效）。CharacterController 本身不会推动刚体，不加这段就推不动箱子。**主机直接施加推力；客户端（P2）通过 `PushCubeServerRpc` 中继给服务器**，服务器做距离（≤1.6m）/速度校验后调用 `PickupCube.ApplyPush`。⚠️ 踩过的坑：若这里写成 `if (!IsServer) return;`，就只有主机玩家推得动箱子，客户端玩家完全推不动。 |
| `Scripts/Puzzle/PickupCube.cs` | 保留服务器权威拾取/搬运；新增 `pushDrag` 阻力（默认 3）与公开的 `ApplyPush(Vector3)`（推箱统一入口），去掉原来的 `OnCollisionStay` 推箱实现。 |
| 新增 `Assets/Materials/CoopSignPanel.mat` | 告示牌深色底板材质。 |

### 关键不变量（改动前务必确认）
1. **图层**：箱子必须在 `Carryable(9)` 层；传递窗屏障在 `CoopChute(10)` 层；两者的**碰撞矩阵已忽略**
   （`Physics.IgnoreLayerCollision(10, 9, true)`，写在 `ProjectSettings/DynamicsManager.asset`）。
   任何一端错层 → 传递窗要么挡住箱子，要么放玩家过去。
2. 场景里的 NetworkObject 都是**场景内放置对象**（不需要注册进 `DefaultNetworkPrefabs`），靠场景加载随场景 spawn。
3. 移动/传送玩家必须走 `PlayerMove.ServerTeleport`，不要直接改 transform（会被同步拉回）。

### 已调参数
- `PickupCube.pickupRange = 1.4`、`holdDistance = 0.9`、`holdHeight = 0.6`、`pushDrag = 3`
- `PlayerMove.pushSpeedFactor = 2.5`（在 `Assets/Prefabs/Player 1.prefab` 上）

## 6. 已知限制与后续

| 项 | 说明 |
|---|---|
| 推箱偏慢 | `pushSpeedFactor` / `pushDrag` 可调；精确摆放建议用 E 拾取搬运 |
| 装饰道具无碰撞 | 货架/木桶/木箱（八方旅人 prefab）本身无 Collider，玩家会穿模走过去；需要时可逐个补 BoxCollider |
| 地板美术未完成 | 8 块 Plane 仍是 URP Lit 素色面，与八方旅人素材风格不统一 |
| 两厅视觉完全相同 | 有意为之（强化"镜像感"），仅出口用蓝/绿区分 |
| Level2 缺 `ChatNetwork` | 同 Level1/Level3 的做法，在大厅/Level2 里补一个即可（本关已补） |
| HD2D 像素化仍失效 | `PixelationFeature` 未挂 Renderer + shader 与 URP 14 Blitter 不兼容（独立任务） |
| 无掉落复活 | 本关南北端已封墙；若后续关卡有高差需补 y 下限检测 |
